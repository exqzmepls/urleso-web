## Project Overview

Urleso Web is the web UI for [Urleso](https://github.com/exqzmepls/Urleso) (a URL shortener): a standalone Blazor WebAssembly app (.NET 8, MudBlazor) served as static files by nginx in Docker. The browser calls the Urleso API directly; this repo talks to the API only through the generated `Urleso.Api.Client`.

The rest of the system (API, redirect service, database) lives in the Urleso repository and is composed there; this repository has its own `docker-compose.yml` that builds and runs just the web container (env vars from `.env`, see `.env.sample`: `WEB_PORT`, `API_BASE_ADDRESS`).

## Commands

```shell
# Build the solution
dotnet build Urleso.Web.sln

# Run the dev server (Urleso API must be running and allow this origin via CORS)
dotnet run --project src/Urleso.Web

# Regenerate the API client from the vendored OpenAPI document (src/Urleso.Api.Client/swagger.json)
dotnet build src/Urleso.Api.Client -c Release -p:ClientGen=True

# Build and run in docker (cp .env.sample .env first time; backend stack from the Urleso repository must be up)
docker compose up -d --build
```

## Architecture

- **src/Urleso.Web** — the Blazor WASM app. `Program.cs` uses `WebAssemblyHostBuilder`, root components `Routes` on `#app` and `HeadOutlet`. Feature code lives in `Api/` (`ApiSettings` options, `IApiClientFactory`/`ApiHttpClientFactory`, `IShortenedUrlService` returning FluentResults) and `Components/` (MudBlazor layout and pages). DI is composed via `Add*` extensions in `Api/DependencyInjection.cs`.
- **src/Urleso.Api.Client** — C# client generated by NSwag (`nswag.json`) from the vendored `swagger.json`. `Client.g.cs`/`Contracts.g.cs` are generated — never edit them by hand. To pick up API changes: regenerate `swagger.json` in the Urleso repo (`dotnet build src/Urleso.Api -p:OpenApiGen=True`), copy it here, then run the client regeneration command above.

### Configuration

`wwwroot/appsettings.json` is downloaded by the browser (container env vars are invisible to WASM). The committed file holds the local-dev API address; in Docker, `docker-entrypoint.d/40-appsettings.sh` regenerates it from the `API_BASE_ADDRESS` env var at container start. `ApiSettings` is bound from the `Api` section; `WebAssemblyHost` does not run startup validators, so `Program.cs` resolves `IOptions<ApiSettings>.Value` eagerly to fail fast.

### Hosting

`Dockerfile` (repo root, build context = repo root): sdk:8.0 publish stage → `nginx:1.27-alpine`. `nginx.conf` listens on 8080 with SPA fallback (`try_files ... /index.html`) and `gzip_static on` to serve the precompressed `.gz` files produced by `dotnet publish`. Unknown paths therefore reach the Blazor router — `Routes.razor` has a `<NotFound>` view.

### Conventions

- NuGet versions are pinned in `src/Directory.Packages.props` (central package management); csproj files reference packages without a `Version` attribute. Shared settings in `src/Directory.Build.props`.
- Logging goes to the browser console via the standard `ILogger`.
