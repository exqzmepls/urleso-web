## Project Overview

Urleso Web is the web UI for [Urleso](https://github.com/exqzmepls/Urleso) (a URL shortener): a Blazor WebAssembly app (.NET 10, MudBlazor) served by a thin ASP.NET Core service that also proxies the API under the app's own origin. The browser only ever talks to this app; the code reaches the API only through the generated `Urleso.Api.Client`.

The rest of the system (API, redirect service, database) lives in the Urleso repository and is composed there; this repository has its own `docker-compose.yml` that builds and runs just the web container (env vars from `.env`, see `.env.sample`: `WEB_PORT`, `API_BASE_ADDRESS`).

## Commands

```shell
# Build the solution
dotnet build Urleso.Web.sln

# Run the app (Urleso API must be running; the service proxies to it, so no CORS setup is needed)
dotnet run --project src/Urleso.Web.Service

# Regenerate the API client from the vendored OpenAPI document (src/Urleso.Api.Client/swagger.json)
dotnet build src/Urleso.Api.Client -c Release -p:ClientGen=True

# Build and run in docker (cp .env.sample .env first time; backend stack from the Urleso repository must be up)
docker compose up -d --build
```

## Architecture

- **src/Urleso.Web.Service** — the ASP.NET Core host. `Program.cs` is the whole thing: a YARP `MapForwarder` for `/api/{**catch-all}`, then `MapStaticAssets()` and `MapFallbackToFile("index.html")` for the client. It references `Urleso.Web` so the client's published `wwwroot` (including `_framework`) lands in this project's static web assets.
- **src/Urleso.Web** — the Blazor WASM app. `Program.cs` uses `WebAssemblyHostBuilder`, root components `Routes` on `#app` and `HeadOutlet`. Feature code lives in `Api/` (`IApiClientFactory`/`ApiHttpClientFactory`, `IShortenedUrlService` returning FluentResults) and `Components/` (MudBlazor layout and pages). DI is composed via `Add*` extensions in `Api/DependencyInjection.cs`.
- **src/Urleso.Api.Client** — C# client generated by NSwag (`nswag.json`) from the vendored `swagger.json`. `Client.g.cs`/`Contracts.g.cs` are generated — never edit them by hand. To pick up API changes: regenerate `swagger.json` in the Urleso repo (`dotnet build src/Urleso.Api -p:OpenApiGen=True`), copy it here, then run the client regeneration command above.

### Configuration

The service owns all configuration. `src/Urleso.Web.Service/appsettings.json` holds the default `Api:BaseAddress`; override it at runtime with `Api__BaseAddress` (`docker-compose.yml` passes `API_BASE_ADDRESS` from `.env`). `appsettings.Development.json` is gitignored and local to each developer. `ApiSettings` is bound from the `Api` section with `ValidateDataAnnotations().ValidateOnStart()`, so a missing or malformed address fails startup rather than the first request.

The WASM client has no configuration of its own and ships no `appsettings*.json`: `Program.cs` points its `HttpClient` at `builder.HostEnvironment.BaseAddress` — the origin the app was served from — and the service proxies `api/*` onward. One image therefore runs in any environment (changing the API address is a restart, not a rebuild), and the API address never reaches the browser.

### Hosting

`src/Urleso.Web.Service/Dockerfile` (build context is still the repo root, so `docker-compose.yml` sets `dockerfile:` explicitly and the `COPY` paths stay `src/...`): sdk:10.0 publish stage → `aspnet:10.0-alpine` listening on 8080. The build deliberately skips the `wasm-tools` workload: relinking the WASM runtime with emscripten needs python in the image and only buys about 40 KB on an already Brotli-compressed ~4.2 MB payload.

`MapStaticAssets()` serves the client's `wwwroot` and `_framework` straight from Kestrel — including the precompressed `.br`/`.gz` files `dotnet publish` produces, with fingerprinted immutable caching. That is what replaced nginx and its Brotli module. Do **not** add `UseBlazorFrameworkFiles()`: its content encoding negotiator runs ahead of routing and dead-ends the request with a 500.

`MapFallbackToFile("index.html")` provides the SPA fallback, so unknown paths reach the Blazor router — `Routes.razor` has a `<NotFound>` view. The `/api/{**catch-all}` forwarder wins over it (a literal prefix beats the fallback's minimal route priority). The forwarder appends the whole request path to the destination, so `/api/shortened-urls` maps 1:1 onto the API — the route pattern filters which requests to proxy, it does not rewrite the path.

### Conventions

- NuGet versions are pinned in `src/Directory.Packages.props` (central package management); csproj files reference packages without a `Version` attribute. Shared settings in `src/Directory.Build.props`.
- Logging uses the standard `ILogger`: the client's goes to the browser console, the service's to container stdout.
